# skill導入・公開依存変更の統括適用

## Decision

この改修は、skill導入、runtimeの公開API移行、OS実機検証、main統合、公開と再導入の受入が連鎖し、責務境界について別ベンダーの反証証跡を必要とする。着手時点で統括レーンの条件を満たす。後にAiterm公開APIの不足も再現し、その製品担当への依存待ちがある。

書込みはPeertable repoとその導入先だけに限定する。Aiterm担当へのAPI要求は別製品の実装指揮や書込権限の移譲を意味しない。Peertableのwriterは親一人であり、既存campaignのControl・Lattice工程を変更しない。公開・受入は親が裁定し、API不足や実機未検証は未完了として残す。
